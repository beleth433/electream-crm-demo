# Локальный помощник ELECTREAM CRM — пилот

CRM и её данные остаются в облаке. Эта программа получает команды по исходящему HTTPS-соединению, обрабатывает их в локальной Ollama и отправляет предложения обратно в CRM. Запись клиентов/техники выполняется только после подтверждения сотрудником в CRM. Программа не открывает компьютер для входящих подключений из интернета и не использует платный API.

## Что уже работает

- Создание клиентов с именем, телефоном и типом; редактирование существующих клиентов по идентификатору, найденному в контексте.
- Добавление до 50 единиц техники за команду по существующим моделям велосипедов и АКБ.
- Задачи по недостающим паспортным данным/прописке курьера, номерам рам/моторов, фактическим серийным номерам и проверке закупочной цены.
- Предложение, уточнение, отмена, подтверждение; повторное подтверждение не дублирует операцию.

В пилоте нет создания моделей, работы с запчастями, продаж, кассы, аренды, ремонтов, удаления и изменения статусов техники. Модели сначала создаются в обычных разделах CRM. Клиент без имени/телефона остаётся запросом на уточнение и не попадает в рабочую базу под вымышленными данными. Одновременно обрабатывается одна команда сотрудника; новые команды остаются в очереди. Обрабатывается контекст до 150 моделей каждого вида и до 30 подходящих клиентов; для более крупных каталогов понадобится поиск с пагинацией.

## Установка на другом компьютере Windows

1. Установить Node.js LTS (22 или новее): https://nodejs.org/ и Ollama: https://ollama.com/ . Для использования моделей проверьте их лицензии и требования оборудования.
2. В Ollama скачать модель командой `ollama pull qwen2.5:3b`, если её ещё нет. Более крупные модели можно выбрать позже на странице настройки. Программа сама ничего не скачивает и не меняет драйверы/настройки GPU.
3. Скопировать **всю папку `local-assistant`** на компьютер клиента или распаковать `build/electream-local-assistant.zip`. Архив собирается из корня проекта командой `powershell -NoProfile -ExecutionPolicy Bypass -File local-assistant/package.ps1`. Исходники остальной CRM и `node_modules` не нужны: программа использует встроенные модули Node.js. Это переносимая папка, пока не отдельный установщик `.exe` и не служба Windows.
4. Дважды открыть `start.cmd` либо в этой папке выполнить `node server.mjs`. Из корня проекта: `npm run assistant:local`.
5. Открыть http://127.0.0.1:47831 . Если Ollama ещё запускается, дождаться списка моделей.
6. В **обновлённой облачной CRM** открыть кнопку «Помощник» в шапке → «Компьютер» → «Получить код подключения».
7. На локальной странице ввести корневой HTTPS-адрес этой CRM (без `/api`), выбрать установленную модель и вставить код. Код одноразовый, действует 10 минут. Пароль от CRM локальной программе не требуется.
8. В CRM открыть «Команды», ввести или продиктовать команду имеющимся приложением транскрибации, дождаться предложения, проверить все значения и нажать «Подтвердить и сохранить».

Процесс Node.js и Ollama должны оставаться запущенными; страницу локальной настройки можно закрыть. После перезагрузки нужно снова запустить `start.cmd`. Автозапуск не устанавливается. С телефона можно отправить команду в ту же облачную CRM от того же сотрудника: её обработает подключённый включённый компьютер. Без интернета или выключенного компьютера команда ждёт подключения.

## Ввод и качество

Встроенного микрофона/распознавания в пилоте нет: используется существующий голосовой ввод в текстовое поле CRM. Текст команды проходит через облачную CRM для очереди; этот вариант не является полностью автономным или полностью локальным хранением данных. Выполнение модели происходит локально. Расходы существующего хостинга CRM остаются.

Уточнения дописываются к исходной команде. Для группы клиентов перечислите каждого; затем можно указать телефоны явно по порядку: «первому …, второму …, третьему …». Тип можно указать один раз: «все трое — курьеры». Для номера, начинающегося с +7 или 8, нужно 11 цифр; короткий/слишком длинный номер не исправляется догадкой. При недостатке данных показываются вопросы с именами клиентов, а не посторонние действия с техникой.

Модель техники должна соответствовать названию в команде либо явно указанным напряжению и ёмкости АКБ. Если запрошенной модели нет в каталоге, помощник спросит о ней и не подставит другую запись. «60 тысяч» распознаётся как 60000; укажите назначение и единицу суммы: «закупочная цена 60 тысяч за каждый». Для неоднозначной «стоимости» будет задан вопрос, а не молча взята цена каталога.

Примеры:

- «Добавь три велосипеда Minako Monster, закупочная цена 45000 рублей за каждый».
- «Добавь четыре АКБ 60 вольт 30 ампер-часов, серийные номера и цену внесу позже».
- «Добавь нового курьера Алексей Смирнов, телефон 79992223344, служба Яндекс Еда. Паспорт и прописку внесу позже».
- «Обнови прописку клиента Иван Иванов с телефоном 79991112233: Самара, улица Ленина, дом 10».

Модель может ошибаться: обязательно проверяйте количество, цену **за единицу**, выбранную модель и все реквизиты. Код отдельно проверяет существование моделей, обязательные поля и присутствие телефона в исходной команде; сервер повторно проверяет права, уникальность номеров и актуальность связанных записей перед сохранением. Это не доказательство истинности всех предложенных моделью данных.

Для нового курьера СНГ сохраняется существующее правило CRM: нужны миграционная карта и патент / статус ЕАЭС. При отсутствии этих данных запрос остаётся на уточнении; помощник не подставляет вымышленные реквизиты или гражданство РФ вместо явно указанного СНГ.

Инвентарные номера велосипедов назначаются автоматически, если не названы. Для АКБ без фактических номеров **явно** используются `ВРЕМ-АКБ-…` и создаются задачи; замените их настоящими номерами до оформления документов. Цены без указания в команде наследуются из модели (либо 0) и требуют отдельной проверки. Добавление техники не проводит закупку/расход в кассе. Покупателям магазина/СТО не создаются задачи по паспорту и прописке. Задачи по заполненным полям автоматически исчезают из списка; фактическая закупочная цена подтверждается вручную кнопкой «Проверено», включая реальную нулевую цену.

Если данные изменились после подготовки предложения, сохранение блокируется: нужно отправить запрос заново. Сеть может вернуть ошибку после сохранения: сначала обновите статус, повторное подтверждение того же запроса безопасно. Ошибки распознавания команды исправляются через «Уточнить запрос»; отмените прежнее предложение, если оно больше не нужно.

## Подключение и хранение

- Локальный сервер слушает только `127.0.0.1:47831`; браузер CRM не обращается к нему через fetch. Очередь обслуживается исходящими запросами к облаку каждые 5 секунд; обработка ограничена четырьмя минутами, аренда задания — пятью, повторная выдача после сбоя — не более трёх попыток.
- В Windows для HTTPS-связи с CRM автоматически читается системный прокси/PAC через .NET. Настройки Windows не меняются. Также поддерживаются `HTTPS_PROXY`/`HTTP_PROXY`. Соединение идёт через CONNECT с обычной проверкой TLS-сертификата; токен CRM не передаётся в заголовках авторизации прокси. Ollama на loopback всегда вызывается напрямую. Это позволяет программе использовать системный маршрут, по которому браузер открывает CRM.
- «Подключение сохранено» и «Есть связь с CRM» — разные состояния. При сетевой ошибке локальная страница показывает понятную причину; в CRM после истечения heartbeat появляется предупреждение и прекращается бесконечная анимация ожидания. Очередь сохраняется и продолжает работу после восстановления связи. Для прерванной обработки есть «Повторить обработку»; если неверно сформирован ответ модели, сразу показывается ошибка. Предложение, загрузка которого оборвалась, повторно отправляется без повторного запуска модели в пределах текущего процесса и аренды задания.
- Локальный токен даёт только получение заданий и отправку предложений этого сотрудника. Он не открывает обычные API CRM и не позволяет подтвердить изменения. Отключение компьютера в CRM, смена пароля или блокировка сотрудника прекращают доступ.
- Настройки и ограниченный токен сохраняются в `%LOCALAPPDATA%\ElectreamCRM\assistant\connection.json` (на других ОС — в пользовательском каталоге данных). Не пересылайте этот файл. Страница настройки не возвращает токен в браузер, проверяет Host/Origin и локальную cookie; CORS наружу не включён.
- Передаётся только контекст разрешённых разделов: названия/ID моделей и подходящие клиенты с именем/телефоном; вся база и фотографии документов в модель не отправляются. Введённые пользователем реквизиты входят в саму команду и сохраняются в истории запросов.
- Последние 30 запросов видны в интерфейсе; завершённые запросы старше 30 суток очищаются при новом запросе. История ограничена 1000 запросами: при достижении лимита удаляются самые старые завершённые запросы, а активные сохраняются. Подтверждённые действия также пишутся в существующий аудит. Задания и задачи хранятся в рабочем JSON/JSONB-снимке `DBStore.assistant` и резервных копиях вместе с CRM. Отдельные таблицы Prisma в этом пилоте не используются.

Необязательные переменные окружения: `CRM_ASSISTANT_PORT`, `CRM_ASSISTANT_DIR` и `OLLAMA_URL` (только loopback). Для теста реальной модели: `node local-assistant/smoke.mjs` из корня проекта; синтетические данные, без сохранения в CRM. `CRM_ASSISTANT_MODEL` выбирает модель только для этой проверки. Проверка локальной программы: `npm run test:assistant-local`; серверных сценариев: `npm test --prefix server`.

Регрессии по групповым клиентам, уточнениям, коротким телефонам, подмене модели и цене в тысячах: `node local-assistant/regression-smoke.mjs`. При переносе обновляйте все файлы из нового ZIP, включая `facts.cjs` и `transport.mjs`.
