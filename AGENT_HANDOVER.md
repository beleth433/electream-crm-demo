## 1. О проекте (Что это за система)

**Courier EBike CRM** — это узкоспециализированная, высокосвязная ERP/CRM-система для коммерческого проката и сервисного обслуживания парка электровелосипедов (Minako Monster, Wenbox U3 Pro и др.) и аккумуляторов, используемых курьерами ключевых служб доставки (**Яндекс Еда, Купер, Самокат, Достависта**).

### Основная ценность системы:
- **Управление парком «в железе»**: Поштучный учет техники по инвентарным номерам (`ЭВ-001`), номерам рам (`FRM-...`) и мотор-колес (`MTR-...`).
- **Два режима аренды**: 
  1. *Классическая посуточная/недельная аренда* с залогом и возвратом;
  2. *Аренда с правом выкупа (Rent-to-Own)* с динамическим расчетом графиков платежей, фиксацией остатка долга и автоматическим переходом права собственности курьеру.
- **Полноценная мастерская (СТО)**: Обслуживание как собственного парка компании (`BIKE`, `BATTERY`), так и прием **сторонней техники клиентов** (`EXTERNAL_DEVICE`).
- **Склад и розничный магазин**: Автоматическое списание запчастей при ремонтах, кассовые розничные чеки, учет экипировки (шлемы, замки, термосумки, зарядные устройства, муфты).
- **Финансы и кадры**: Учет зарплат (оклады, за смену, сдельная за ремонты), фискальные чеки, расчет P&L, выручки и коэффициента утилизации парка (Fleet Utilization %).
- **Симулятор входящего потока курьеров**: Встроенный движок со сжатием времени ($1 \text{ день} = 15 \text{ минут}$), позволяющий проверять CRM в реальном времени.

## 2. Структура кодовой базы и технологический стек

Проект организован как чистый TypeScript-монорепозиторий:

```
courier-ebike-crm/
├── ARCHITECTURE.md          # КЛЮЧЕВОЙ ДОКУМЕНТ: Архитектурные связи, формулы, матрицы
├── AGENT_HANDOVER.md        # Настоящий документ передачи проекта
├── README.md                # Публичное описание и быстрый старт
├── package.json             # Корневой package (скрипты dev, build)
├── docker-compose.yml       # Опциональный запуск PostgreSQL 16
│
├── client/                  # Frontend (React 18, Vite, TypeScript, Tailwind CSS)
│   ├── src/
│   │   ├── components/      # UI-компоненты (TimeMachine, Модалки, Drawer симуляции)
│   │   ├── context/         # React Contexts (SimulationContext, ThemeContext)
│   │   ├── data/            # Сценарии симуляции, шаблоны экипировки
│   │   ├── pages/           # Основные экраны CRM (см. Раздел 3)
│   │   ├── services/        # API-клиент (axios / fetch к бэкенду)
│   │   ├── types/           # Полные TypeScript-интерфейсы всех сущностей
│   │   ├── App.tsx          # Корневой лейаут, навигация, табы
│   │   ├── main.tsx         # Точка входа React
│   │   └── index.css        # Tailwind стили, шрифт Rubik
│   └── package.json
│
└── server/                  # Backend (Node.js 22, Express, TypeScript, Zod, Prisma)
    ├── data/
    │   └── crm_db.json      # Автономная база данных JSON DAL (Zero-Config Persistence)
    ├── prisma/
    │   ├── schema.prisma    # Реляционная схема для PostgreSQL
    │   └── seed.ts          # Скрипт наполнения данными
    ├── src/
    │   ├── controllers/     # HTTP-контроллеры эндпоинтов
    │   ├── dtos/            # Zod-схемы валидации входящих запросов
    │   ├── repositories/    # Слой доступа к данным (db.ts — JSON движок)
    │   ├── services/        # Бизнес-логика, транзакции, стейт-машины
    │   ├── routes/          # Express роутинг (/api/*)
    │   └── index.ts         # Запуск Express сервера (порт 4000)
    └── package.json
```

### Стек технологий:
- **Frontend**: React 18, Vite, TypeScript, Tailwind CSS, Lucide React (иконки), TanStack Query v5, Zod, Sonner (всплывающие тосты), локальный шрифт **Rubik**.
- **Backend**: Node.js 22, Express, TypeScript, Zod (строгая валидация входящих DTO), Multer (загрузка фото документов курьеров).
- **Хранение данных (Двойной движок)**:
  1. **Встроенный автономный JSON DAL** (`server/data/crm_db.json` через `server/src/repositories/db.ts`) — позволяет мгновенно работать «из коробки» без внешних баз, сохраняя все сущности на диск при каждом изменении.
  2. **Prisma ORM** (`prisma/schema.prisma`) — production-ready схема для PostgreSQL 16.

## 3. Ключевые страницы и функциональные узлы

1. **`BikesPage` (Электровелосипеды)**:
   - Каталог моделей байков (`BikeModel`: мощность, диаметр колес, базовая цена аренды, выкупная цена).
   - Список физических байков (`Bike`: инвентарный номер, номер рамы, мотор-колеса, статус, прикрепленный АКБ).
2. **`BatteriesPage` (Аккумуляторы)**:
   - Модели АКБ (`BatteryModel`: вольтаж 48V/60V, емкость Ah, химия, цена).
   - Физические батареи (`Battery`: серийный номер, статус, процент здоровья SOH, циклы).
3. **`RentalsPage` + `RentalWizardModal` + `RentalCloseModal` (Договоры аренды и выкупа)**:
   - Пошаговый мастер выдачи (клиент $\rightarrow$ байк $\rightarrow$ батареи $\rightarrow$ экипировка $\rightarrow$ тариф $\rightarrow$ кассовый чек).
   - Режим **Аренда с выкупом (Rent-to-Own)**: математически выверенный график, двухсторонняя реактивная связь платежа и срока, учет добавленных АКБ.
   - Печатный двусторонний **Акт приема-передачи** с реквизитами, номерами оборудования и подписями.
4. **`RepairsPage` (Мастерская СТО)**:
   - Заказ-наряды на ремонт.
   - Поддерживает 3 типа техники:
     - `BIKE` (велосипед парка);
     - `BATTERY` (АКБ парка);
     - `EXTERNAL_DEVICE` (**Сторонняя техника** — личный транспорт курьера или клиента СТО).
   - Разделение ответственности: `COMPANY_EXPENSE` (износ, за счет сервиса) или `CLIENT_FAULT` (вина клиента).
   - Автоматическое транзакционное списание запчастей со склада при завершении заказа (`COMPLETED`).
5. **`WarehousePage` / `InventoryPage` (Склад запчастей)**:
   - Учет колодок, камер, контроллеров, ручек газа.
   - Минимальный порог остатков с индикацией необходимости дозаказа.
6. **`OutfitsPage` (Экипировка)**:
   - Шлемы, 10-мм противоугонные замки, курьерские термосумки, зарядные устройства, муфты на руль.
7. **`ClientsPage` (База курьеров и покупателей)**:
   - Проверка паспорта РФ или комплекта документов СНГ (миграционная карта, патент).
   - Фиксация службы доставки (Яндекс, Купер, Самокат).
   - Статусы: `NORMAL`, `VIP`, `PROBLEM`, `BLACKLIST` (блокировка выдачи в аренду).
   - Программа лояльности с автоматическими скидками.
8. **`ShopPage` (Розничная касса)**:
   - Продажа запчастей и экипировки за наличные, карту или СБП с печатью товарного чека.
9. **`FinancePage` (Финансовый контур и аналитика)**:
   - Все транзакции, фильтры по типам платежей, P&L, выручка, маржа, Fleet Utilization %.
10. **`EmployeesPage` (Сотрудники и смены)**:
    - Учет мастеров и менеджеров, расчет заработной платы (оклад, выход за смену, сдельная за заказ-наряды).
11. **`KnowledgeBasePage` (База знаний)**:
    - Регламенты приемки, зимней эксплуатации аккумуляторов 60V, скрипты общения с курьерами.
12. **`SimulationEngine` (Симуляция)**:
    - Верхний тулбар «Машина времени».
    - Боковая панель очереди клиентов с реалистичными диалогами, готовыми действиями для быстрого онбординга или оформления ремонта в один клик.

## 4. Железные правила и этика проекта (КРИТИЧНО)

Пользователь (владелец проекта) предъявляет жесткие требования к качеству и поведению ИИ-ассистента:

### ⚠️ Правило 1: ОБЯЗАТЕЛЬНОЕ СОГЛАСОВАНИЕ (User-First)
- **Перед добавлением любых новых функций, кнопок, модальных окон или изменением дизайна агент ОБЯЗАН спросить пользователя и предложить варианты.**
- Запрещено самовольно навешивать на экран несогласованные кнопки-шаблоны или пресеты (например, плашки быстрых подсказок, которые загромождают форму).

### ⚠️ Правило 2: ЧИСТОТА И ПРОФЕССИОНАЛИЗМ ТЕРМИНОЛОГИИ
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать разговорные или пренебрежительные выражения вроде *«с улицы»*, *«клиент с улицы»*.
- Используйте исключительно официальные формулировки:
  - Для техники: **«Сторонняя техника»** или **«Техника клиента»**;
  - Для клиента: **«Новый клиент»** или **«Клиент СТО»**;
  - Для заказа: **«Частный заказ»** или **«Заказ-наряд СТО»**.

### ⚠️ Правило 3: ИСКЛЮЧИТЕЛЬНО РУССКИЕ ИМЕНА
- Во всех плейсхолдерах (`placeholder="Иван Иванов"`), моках, сидах и сценариях симуляции **использовать только стандартные русские имена** (Иван Иванов, Алексей Смирнов, Дмитрий Кузнецов, Сергей Морозов, Максим Новиков и т.д.). Никаких среднеазиатских имен.

### ⚠️ Правило 4: СВОБОДА РУЧНОГО ВВОДА
- Автоматические формулы и калькуляторы (например, расчет выкупа или рекомендованная цена ремонта) служат лишь помощником. **Все итоговые поля сумм, сроков и дат всегда должны оставаться доступными для прямого ручного редактирования пользователем.**

## 5. Запуск окружения и команды для разработки

### Порты сервисов:
- **Backend API**: `http://localhost:4000` (Healthcheck: `http://localhost:4000/health`)
- **Frontend Vite**: `http://localhost:3000`

### Основные команды (запускаются из корня):
```bash
# Одновременный запуск фронтенда и бэкенда в режиме разработки:
npm run dev

# Раздельный запуск:
npm run dev:server    # запуск Express через tsx watch
npm run dev:client    # запуск Vite

# Полная сборка проекта (Backend tsc + Frontend tsc & vite build):
npm run build
```

> **Важно**: Перед каждым коммитом в Git обязательно выполняйте `npm run build`. Сборка должна завершаться с кодом 0 без ошибок TypeScript.
